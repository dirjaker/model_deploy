# 本地模型部署 + 推理优化 — 技术设计文档

> 项目定位：一个完整的本地大模型部署方案，支持模型量化、推理加速、API 兼容、多模型管理，让企业可以在自有硬件上低成本、高性能地运行大模型。

---

## 一、项目背景与价值

### 1.1 为什么做这个项目？

很多企业有数据隐私要求（金融、医疗、政务），不能把数据发到外部 API。本地部署大模型是刚需，但面临几个核心挑战：

1. **显存不够**：70B 模型需要 140GB 显存（FP16），消费级显卡跑不动
2. **速度太慢**：原始 PyTorch 推理吞吐量低，无法支撑生产流量
3. **接口不兼容**：现有应用都是按 OpenAI API 格式开发的
4. **运维困难**：模型加载、显存管理、故障恢复都需要自动化

这个项目展示了：
- 对 **模型推理全链路** 的深入理解（量化 → 加速 → 服务 → 监控）
- 对 **GPU 编程和系统优化** 的实践能力
- 对 **生产级部署** 的工程化思维

### 3.2 模型量化模块 (`quantizer.py`)

#### 3.2.1 量化技术对比

| 量化方法 | 位数 | 精度损失 | 速度提升 | 显存节省 | 适用场景 |
|---------|------|---------|---------|---------|---------|
| **GPTQ** | 2-8 bit | 低 | 中 | ~75% (4-bit) | GPU 推理，精度敏感 |
| **AWQ** | 4-bit | 最低 | 高 | ~75% | GPU 推理，速度优先 |
| **GGUF** | 2-8 bit | 可调 | 中 | 可调 | CPU/混合推理 |

#### 3.2.2 架构设计

采用 **工厂模式 + 抽象基类**：

```
BaseQuantizer (抽象基类)
├── GPTQQuantizer    # 基于二阶信息的量化
├── AWQQuantizer     # 激活值感知权重量化
└── GGUFQuantizer    # llama.cpp 量化格式

QuantizerFactory     # 统一创建接口
quantize_model()     # 便捷函数
```

**核心接口：**
- `quantize(model_path, output_path)` → 执行量化并保存
- `validate(model_path)` → 验证量化模型完整性
- `get_output_path()` → 自动推断输出路径

**量化配置 (`QuantizationConfig`)：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `bits` | 4 | 量化位数（2/3/4/8） |
| `group_size` | 128 | 分组大小 |
| `desc_act` | False | 是否按激活值降序排列 |
| `sym` | True | 是否对称量化 |
| `true_sequential` | True | 是否逐层顺序量化 |
| `num_samples` | 128 | 校准样本数 |

#### 3.2.3 GPTQ 量化原理

```
1. 加载原始 FP16 模型
2. 准备校准数据集（128-256 条样本）
3. 逐层量化：
   a. 计算 H = X^T * X（Hessian 矩阵的近似）
   b. 对每一列：找到最优量化参数 → 量化权重 → 误差传播（OBQ 方法）
4. 保存量化模型 + 元数据
```

#### 3.2.4 AWQ 量化原理

```
核心思想：不是均匀量化所有权重，而是保护"重要"通道
- 重要通道 = 激活值大的通道
- 对重要通道用缩放因子保护
- 搜索每个通道的最优缩放因子 s，然后量化 W * s

优势：比 GPTQ 精度更高（尤其在 4-bit 下），推理速度更快
```

#### 3.2.5 GGUF 量化

GGUF 是 llama.cpp 使用的格式，支持 CPU 推理：

| 量化类型 | 位数 | 质量 | 大小比例 |
|---------|------|------|---------|
| Q2_K | 2-bit | 低 | 0.15x |
| Q3_K_M | 3-bit | 中低 | 0.20x |
| Q4_K_M | 4-bit | 中（推荐） | 0.25x |
| Q5_K_M | 5-bit | 中高 | 0.35x |
| Q6_K | 6-bit | 高 | 0.40x |
| Q8_0 | 8-bit | 极高 | 0.50x |

### 3.3 推理引擎 (`inference_engine.py`)

#### 3.3.1 架构设计

```
BaseInferenceEngine (抽象基类)
├── MockInferenceEngine    # 模拟引擎（无 GPU 环境测试）
└── VLLMInferenceEngine    # vLLM 高性能引擎

InferenceEngineFactory     # 工厂类，按配置创建引擎
```

**引擎状态机：**

```
INITIALIZING → READY → BUSY → READY → SHUTDOWN
                  ↘ ERROR ↗
```

**核心接口：**
- `initialize()` → 初始化引擎
- `shutdown()` → 关闭引擎
- `chat_completion(request)` → 聊天补全
- `chat_completion_stream(request)` → 流式聊天补全
- `completion(request)` → 文本补全
- `completion_stream(request)` → 流式文本补全

#### 3.3.2 MockInferenceEngine

用于 **无 GPU 环境** 的测试和演示：
- 模拟模型加载延迟
- 基于 prompt hash 选择预设响应
- 支持流式分块输出
- 完整的指标统计（请求计数、延迟、token 数等）

#### 3.3.3 VLLMInferenceEngine

集成 vLLM 高性能推理引擎，核心优化技术：

| 技术 | 说明 | 效果 |
|------|------|------|
| **PagedAttention** | 按页管理 KV Cache（类似 OS 虚拟内存） | 显存利用率提升 2-4 倍 |
| **Continuous Batching** | 请求完成立即释放，新请求立即加入 | 吞吐量提升 2-3 倍 |
| **Tensor Parallelism** | 模型权重分布到多张 GPU | 支持多卡推理大模型 |
| **Prefix Caching** | 相同前缀复用 KV Cache | 重复前缀推理加速 |

#### 3.3.4 推理指标 (`InferenceMetrics`)

| 指标 | 说明 |
|------|------|
| `total_requests` | 总请求数 |
| `successful_requests` | 成功请求数 |
| `failed_requests` | 失败请求数 |
| `total_tokens_generated` | 生成的总 token 数 |
| `avg_latency` | 平均延迟（秒） |
| `active_requests` | 当前活跃请求数 |
| `queued_requests` | 排队请求数 |

### 3.4 模型管理器 (`model_manager.py`)

#### 3.4.1 核心功能

| 功能 | 方法 | 说明 |
|------|------|------|
| **加载模型** | `load_model(config)` | 创建引擎 → 初始化 → 更新状态 |
| **卸载模型** | `unload_model(name)` | 关闭引擎 → 释放资源 → 删除状态 |
| **切换模型** | `switch_model(from, to)` | 卸载旧模型 → 加载新模型 |
| **空闲清理** | `cleanup_idle_models()` | 自动卸载超过空闲时间的模型 |
| **显存监控** | `GPUMemoryMonitor` | 获取显存信息、估算模型显存需求 |
| **状态查询** | `get_system_status()` | 返回模型数、显存、请求数、运行时间等 |

#### 3.4.2 模型状态机

```
UNLOADED → LOADING → READY → UNLOADING → UNLOADED
                 ↘ ERROR ↗
```

#### 3.4.3 显存估算策略

- GPTQ/AWQ 量化模型：`基础大小 × 0.25`（4-bit 约为原始的 1/4）
- GGUF 量化模型：`基础大小 × 0.3`
- FP16 全精度：基础大小（7B 约 14GB）

#### 3.4.4 并发安全

所有模型状态变更操作通过 `asyncio.Lock` 保护，确保多请求并发时状态一致性。

## 五、技术栈总结

| 模块 | 技术选型 | 说明 |
|------|---------|------|
| **推理引擎** | vLLM | PagedAttention + Continuous Batching |
| **量化工具** | AutoGPTQ / AutoAWQ / llama.cpp | 4-bit 量化，精度损失 < 1% |
| **API 框架** | FastAPI + Uvicorn | 异步高性能，OpenAI 兼容接口 |
| **数据验证** | Pydantic v2 | 类型安全的请求/响应模型 |
| **监控** | Prometheus Client + psutil | GPU/CPU 指标采集 |
| **配置管理** | YAML + Pydantic | 结构化配置 + 类型校验 |
| **GUI** | tkinter | macOS 桌面客户端 |
| **打包** | py2app | macOS .app 应用打包 |
